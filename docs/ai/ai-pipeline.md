# AI Pipeline — Kisan Dost AI

This document defines exactly what Zain's work must produce so it plugs into the backend without rework. Read `docs/architecture/system-architecture.md` first for the overall pipeline shape.

## Pipeline Recap

```
Leaf Image → CV Model (Zain) → {disease, confidence}
   → Knowledge Lookup (Zain builds the data, Talal's service reads it)
   → + Weather + Crop context (Talal's services)
   → Recommendation logic (Talal)
   → LLM explanation (Zain writes prompts, Talal wires the call)
   → Response
```

## 1. CV Model — Selection Criteria

Do NOT train a model from scratch. Evaluate 2-3 **pretrained** plant-disease classification models (HuggingFace, trained on PlantVillage or similar) and pick one based on:

- Class coverage: does it cover our priority crops/diseases (list below)?
- Accuracy on those specific classes, not just overall benchmark accuracy
- Inference latency (needs to feel responsive in a live demo — test actual response time, not just claimed benchmarks)
- Whether it's servable via HuggingFace Inference API without a local GPU

## 2. CV Provider Output Contract

Whatever model you pick, `backend/app/providers/cv/hf_plant_model.py` (which you implement) must return **exactly** this shape to the service layer:

```json
{
  "disease_label": "tomato_early_blight",
  "confidence": 0.94
}
```

- `disease_label`: a snake_case key that maps to an entry in the knowledge base (section 3below) — agree on the exact label taxonomy with Talal before writing code, since this is the join key between your provider and his service.
- `confidence`: float 0.0–1.0.

Do not return prose, treatment info, or anything else from this layer — that's the knowledge base's job, not the model's.

---

## 3. Knowledge Base Structure

File: `backend/app/knowledge/diseases.json`

This is **structured data you write and maintain** — not generated by the LLM at runtime. One entry per `disease_label`:

```json
{
  "tomato_early_blight": {
    "display_name": "Tomato Early Blight",
    "crop": "tomato",
    "symptoms": [
      "Dark concentric-ring spots on lower leaves",
      "Yellowing around lesions"
    ],
    "causes": [
      "Fungal pathogen (Alternaria solani)",
      "Favored by warm, humid conditions"
    ],
    "treatment": [
      "Apply copper-based or chlorothalonil fungicide",
      "Remove and destroy infected leaves"
    ],
    "prevention": [
      "Crop rotation",
      "Avoid overhead watering",
      "Ensure adequate plant spacing"
    ],
    "severity_default": "moderate",
    "weather_risk_factors": {
      "humidity_threshold": 75,
      "rain_increases_risk": true
    }
  }
}
```

**Rules for content:**
- No exact fertilizer dosage numbers — general guidance only, defer to local agricultural extension guidance or product labels (this came directly from the hackathon brief's own caution against unsupported dosage claims).
- Every claim should be something you'd be comfortable defending if a judge asks "where did that come from?" — prefer well-established agricultural knowledge over anything uncertain.
- Cover all diseases your chosen CV model can output — an unmapped `disease_label` will break the pipeline, so the knowledge base must have 100% coverage of the model's output classes.

## 4. LLM Prompt Design (for the chat/explanation layer)

You write the system prompt(s); Talal wires the actual API call in `backend/app/providers/llm/qwen_provider.py`.

**For disease explanation** (turning structured data into natural language):
- Input to the LLM: the knowledge base entry + weather context + crop context (as JSON)
- Instruction: explain in the requested language (en/ur), conversational but accurate, do not add facts not present in the input JSON, do not invent additional treatment options
- Keep responses concise — a farmer on a phone doesn't want a paragraph wall

**For open-ended chat** (farmer asks a free-form question):
- Give the LLM the farmer's crop/scan history context where available (Talal's service provides this)
- Instruction: be a knowledgeable, friendly farming assistant; when unsure of a fact, say so rather than guessing; support both English and Urdu naturally based on the `language` field in the request

## 5. Testing Responsibility

Before any disease/pest result ships, spot-check: does the CV model's confidence correlate with actually-correct predictions on a handful of real test images? Flag any class where the model performs poorly — better to know before demo day than during it.
